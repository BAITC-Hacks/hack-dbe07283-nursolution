## Режим работающего сервера

`GET /health` возвращает готовность каталога, `total_profiles`, `catalog_backend`
(`csv` / `postgres`) и `llm_enabled`. Последнее отражает фактическую настройку
процесса, включая переопределения окружения. Оно не подтверждает валидность
ключа или успешность последнего запроса к OpenAI.

В `/match` источник каждой карточки указан в `explanation_source`: `openai` или
`python`. `warning` объясняет резервный режим. Источник `openai` может означать
сохранённый ответ: для проверки нового вызова сравните `provider_calls` до и после
запроса либо выполните поиск после перезапуска процесса с пустым кешем.

## Агрегаты

`GET /metrics` возвращает JSON со статистикой **текущего процесса**:

- `uptime_seconds` — время с создания сервиса объяснений;
- `counters` — счётчики событий; отсутствующий счётчик ещё не увеличивался;
- `durations` — `count`, `total_seconds`, `max_seconds`, `mean_seconds`.

| Счётчик | Что означает |
| --- | --- |
| `http_match_2xx`, `http_match_4xx`, `http_match_5xx` | Результаты HTTP-обработки `/match` |
| `provider_calls` | Начатые вызовы генерации через провайдера, без попаданий в кеш |
| `provider_success` | Ответы, целиком прошедшие проверку содержания |
| `provider_invalid` | Ответы с частичной заменой неподтверждённых цитат |
| `provider_errors` | Исключения при создании клиента, запросе или проверке ответа |
| `cache_hit`, `cache_miss` | Наличие / отсутствие готового результата в кеше |
| `shared_wait` | Ожидания уже выполняющегося одинакового запроса |
| `offline`, `missing_key` | Локальные ответы из-за режима или отсутствия ключа |
| `saturated` | Отказы от нового вызова из-за лимита параллелизма |
| `deadline_before_lookup`, `wait_timeout`, `late_result` | Истечение дедлайна на разных этапах |

Длительности `http_match` включают обработку HTTP-запроса, `provider` — работу
провайдера вместе с проверкой ответа. `provider_success` может сопровождаться
`late_result`: корректный, но поздний результат клиенту уже не доставляется.
`cache_miss` не всегда приводит к новому вызову: возможны общее ожидание и лимит.

Метрики не содержат ключей, описаний, имён, городов и тела запросов. Endpoint не
требует ключа редактора и предназначен для диагностики локального приложения.
Это JSON-агрегаты, не Prometheus exposition format. Истории, процентилей, дашборда
и сбора статистики нескольких workers пока нет; перезапуск обнуляет значения.

## Журнал запросов

Каждый `/match` получает `X-Request-ID`. В серверный журнал записывается событие
`match_completed` с этим идентификатором, HTTP-статусом и длительностью в секундах.
Параметры заказа и Authorization в это событие не включаются.

```bash
docker compose logs --tail=100 web
```

Обычный access log Uvicorn сохраняется отдельно. Внутренние ошибки API возвращаются
клиенту без трассировки. Длительность не является гарантией SLA: зависание базы,
сеть и нагрузка требуют отдельного мониторинга и нагрузочных испытаний.
