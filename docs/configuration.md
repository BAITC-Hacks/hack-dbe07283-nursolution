# Настройки и запуск

[README](../README.md) · [API](api.md) · [Архитектура](architecture.md)

Быстрый запуск без OpenAI и локальная установка описаны в [README](../README.md#быстрый-запуск).
Все команды ниже выполняются из корня проекта.

## Файл окружения

Образец настроек — [`.env.example`](../.env.example). Рабочий файл `.env` находится в корне,
игнорируется Git и не копируется в Docker-образ. Если в нём уже есть ключ, сохраняйте файл
и добавляйте недостающие переменные вручную.

Создать файл, только если он отсутствует:

**PowerShell:**

```powershell
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
```

**Bash:**

```bash
if [ ! -f .env ]; then cp .env.example .env; fi
```

В образце `MATCHER_USE_LLM=true`, а ключ — заглушка. Для демо установите `false`;
для работы с AI замените заглушку действующим ключом.

## Переменные

Значения в таблице — значения по умолчанию в коде и Compose, если нет переопределений.

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `OPENAI_API_KEY` | Пусто | Серверный ключ для OpenAI |
| `MATCHER_USE_LLM` | `true` в локальном API, `false` в Docker | Включение выбора цитат моделью; допустимы `true`, `false`, `1`, `0` |
| `MATCHER_TIMEOUT_SECONDS` | `8` | Бюджет запроса в секундах: больше 0, не больше 9 |
| `EXPLANATION_CACHE_TTL_SECONDS` | `600` | TTL кеша в секундах; 0 отключает хранение |
| `EXPLANATION_CACHE_MAX_ENTRIES` | `256` | Максимальное число записей; целое число ≥ 0 |
| `LLM_MAX_CONCURRENCY` | `4` | Максимум незавершённых LLM-вызовов на процесс; целое число ≥ 1 |
| `APP_PORT` | `8080` | Порт на хосте для Docker Compose |
| `CORS_ORIGINS` | Локальные origins | Разрешённые адреса браузерных клиентов через запятую, без путей |
| `MATCHER_CSV_PATH` | CSV из `data/` | Путь к другому CSV при локальном запуске API |

Локально CORS разрешает `localhost` и `127.0.0.1` на портах `5173` и `3000`;
Compose по умолчанию задаёт эти хосты на порту `8080`. При фронтенде и API на одном
адресе CORS не требуется. `.env.example` содержит локальные origins для разработки.

`APP_PORT` не меняет порт локального Uvicorn: его задаёт параметр `--port`.
`MATCHER_CSV_PATH` не передаётся в контейнер текущим Compose. Чтобы заменить каталог
в Docker, обновите CSV в `data/` и пересоберите образ. Относительный пользовательский
путь CSV отсчитывается от рабочей директории; стандартный путь — от корня проекта.

Переменные оболочки имеют приоритет над `.env`. Локальное приложение читает `.env`
через `python-dotenv`, а Compose подставляет значения в `environment` контейнера.
Изменение файла само по себе не обновляет уже работающий процесс.

## Включение OpenAI

1. Создайте `.env`, если его нет, и задайте действующий `OPENAI_API_KEY`.
2. Установите `MATCHER_USE_LLM=true`.
3. Уберите установленное ранее переопределение офлайн-режима и пересоздайте контейнер.

**PowerShell:**

```powershell
Remove-Item Env:MATCHER_USE_LLM -ErrorAction SilentlyContinue
docker compose up -d --wait
```

**Bash:**

```bash
unset MATCHER_USE_LLM
docker compose up -d --wait
```

При локальном запуске после снятия переопределения перезапустите Uvicorn.
Приложение использует `gpt-4o-mini` с `temperature=0.0`; модель задаётся в
[`app/services/prompts.py`](../app/services/prompts.py).

Интерфейс при открытии автоматически выполняет демонстрационный подбор.
При включённом AI и отсутствии кеша это вызывает OpenAI. В ответе `/match`
`explanation_source="openai"` означает, что модель выбрала проверенную цитату
(возможно, ранее сохранённую в кеше). `python` означает локальный выбор.
`/health` проверяет каталог, а не ключ и доступность OpenAI.

Прямой `EventMatcher()` по умолчанию разрешает LLM независимо от `MATCHER_USE_LLM`:
для офлайн-интеграции передайте `EventMatcher(use_llm=False)`. Для CLI используйте `--offline`.

## Docker

| Сервис / цель | Назначение |
| --- | --- |
| `web` / `runtime` | API, фронтенд и каталог в одном образе |
| `tests` / `test` | Одноразовый запуск тестов; офлайн-режим и пустой API-ключ |

Приложение работает от пользователя без root. Compose задаёт read-only файловую
систему, временный `/tmp`, `no-new-privileges`, удаление capabilities и ротацию логов.
Проверка здоровья обращается к `/health`. Тесты и зависимости разработки не входят
в итоговый runtime-образ.

```bash
docker compose config --quiet
docker compose ps
docker compose logs --tail=100 web
docker compose run --build --rm tests
docker compose down
```

## Если запуск не удался

| Симптом | Что проверить |
| --- | --- |
| Docker недоступен | Запущен ли Docker Engine / Desktop, выбран ли режим Linux-контейнеров |
| Порт `8080` занят | Задайте другой `APP_PORT` в `.env`, повторите `docker compose up -d --wait` и откройте новый порт |
| После правки кода поведение прежнее | Пересоберите: `docker compose up --build -d --wait` |
| AI не включается после правки `.env` | Проверьте переопределение `MATCHER_USE_LLM` в оболочке и перезапустите процесс |
| Карточки есть, источник `python` | Проверьте режим, ключ и поле `warning`; так же работает резервный ответ при таймауте или ошибке модели |
| API не стартует с новым CSV | Посмотрите логи: загрузчик проверяет обязательные поля, уникальность `id`, числа и даты |

Ключ не нужно передавать в браузер или публиковать в репозитории. Для проверки
синтаксиса Compose достаточно `config --quiet`: полный вывод `config` содержит подставленные настройки.
