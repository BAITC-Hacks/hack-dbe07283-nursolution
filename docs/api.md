# HTTP API

[README](../README.md) · [Архитектура](architecture.md) · [Настройки](configuration.md)

Базовый адрес при запуске через Docker: `http://localhost:8080`.
При локальном запуске Uvicorn по инструкции из README: `http://localhost:8000`.
Запросы и ответы используют JSON; авторизация в текущей версии отсутствует.

## Маршруты

| Метод | Путь | Назначение |
| --- | --- | --- |
| `GET` | `/` | Веб-интерфейс |
| `GET` | `/health` | Готовность каталога и число профилей |
| `GET` | `/catalog` | Варианты полей формы из CSV |
| `POST` | `/match` | Подбор подрядчиков |
| `GET` | `/docs` | Swagger UI |
| `GET` | `/openapi.json` | Машиночитаемые схемы API |

## Запрос подбора

`POST /match`, заголовок `Content-Type: application/json`:

```json
{
  "city": "Алматы",
  "date": "2026-09-26",
  "event_type": "корпоратив",
  "category": "Ведущий",
  "budget": 1000000,
  "language": "русский",
  "duration": 4
}
```

| Поле | Тип | Обязательное | Правила |
| --- | --- | --- | --- |
| `city` | string | Да | Непустое название города |
| `date` | string | Да | Существующая календарная дата в формате `YYYY-MM-DD` |
| `event_type` | string | Да | Формат мероприятия |
| `category` | string | Да | Категория подрядчика |
| `budget` | number | Да | Конечное число ≥ 0, в тенге |
| `language` | string или null | Нет | Непустой язык работы, если задан |
| `duration` | number или null | Нет | Конечное число > 0, в часах |

`language` и `duration` можно опустить. Текстовые поля, кроме даты, ограничены 200 символами;
пробелы по краям удаляются. Сопоставление названий не зависит от регистра.
Неизвестные поля, числовые строки и логические значения вместо чисел отклоняются.
Прошедшие даты не запрещены: дата проверяется на корректность и занятость в каталоге.

## Ответ подбора

Все три бизнес-исхода возвращаются с **HTTP 200** и схемой `MatchResponse`.

| `status` | Значение для пользователя |
| --- | --- |
| `matched` | Подобраны от одного до трёх подрядчиков |
| `no_category_in_city` | В выбранном городе нет такой категории |
| `no_matches` | Категория в городе есть, но ни один профиль не прошёл условия |

| Поле | Содержание |
| --- | --- |
| `cards` | Список карточек, от 0 до 3 |
| `message` | Объяснение результата, включая причину выдачи менее трёх карточек |
| `total_profiles` | Число всех загруженных профилей |
| `scope_count` | Число профилей в выбранных городе и категории до остальных фильтров |
| `eligible_count` | Число прошедших все условия до ограничения TOP-3 |
| `rejection_counts` | Счётчики первых причин отказа |
| `suggestions` | Проверенные изменения одного поля; пустой список, если подсказок нет |
| `warning` | Предупреждение о резервном объяснении либо `null` |

Карточка содержит `id`, `anon_name`, `category` (категория запроса), `categories`
(все категории профиля), `city`, `price_from_kzt`, `explanation`, `explanation_source` и `evidence`.
`explanation_source` равен `python` или `openai`. Во втором случае модель выбрала цитату,
но окончательный текст проверен и собран Python. Кешированный AI-ответ также имеет источник `openai`.
`evidence` — объект `{"field": "description", "quote": "…"}` либо `null`.

### Счётчики и подсказки

Причины отказа: `city`, `category`, `budget`, `date`, `event_type`, `language`,
`duration`, `duration_unknown`. Один профиль учитывается только по первой причине
в порядке фильтрации. Эти счётчики нельзя трактовать как независимые причины для всех профилей.

```text
sum(rejection_counts.values()) + eligible_count == total_profiles
```

Подсказка содержит `field`, `value`, `candidate_count`, `candidate_ids`, `message`.
Допустимые поля: `budget`, `date`, `event_type`, `language`, `duration`.
Она проверена повторной фильтрацией с изменением ровно одного условия; остальные остаются прежними.
При применении подсказки клиент отправляет новый запрос. Детали алгоритма — в
[архитектуре](architecture.md#четыре-этапа).

### Вызов из фронтенда

Для интерфейса, который отдаёт сам API, используйте относительный адрес:

```javascript
const order = {
  city: "Алматы",
  date: "2026-09-26",
  event_type: "корпоратив",
  category: "Ведущий",
  budget: 1000000,
};
const response = await fetch("/match", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify(order),
});
const result = await response.json();
if (!response.ok) throw new Error(result.error.message);
console.log(result.status, result.cards, result.message);
// Для применения подсказки повторите запрос с:
// { ...order, [suggestion.field]: suggestion.value }
```

Если фронтенд размещён отдельно, задайте полный адрес API и подходящий
[`CORS_ORIGINS`](configuration.md#переменные).

## Ошибки

| HTTP | `error.code` | Причина |
| --- | --- | --- |
| 422 | `validation_error` | Некорректное тело запроса или значения полей |
| 404 | `http_error` | Неизвестный маршрут |
| 405 | `http_error` | Метод не разрешён для маршрута |
| 500 | `internal_error` | Неожиданная внутренняя ошибка |

Пример для отрицательного бюджета:

```json
{
  "error": {
    "code": "validation_error",
    "message": "Проверьте параметры запроса.",
    "fields": [
      {
        "field": "budget",
        "message": "Значение должно быть неотрицательным.",
        "type": "greater_than_equal"
      }
    ]
  }
}
```

Внутренняя ошибка возвращается без трассировки и служебных данных.
Недоступность OpenAI не превращает успешный подбор в HTTP 500: возвращаются
карточки с объяснениями Python и предупреждением. При пустом подборе LLM не вызывается.

## Каталог и готовность

`GET /catalog` возвращает `total_profiles` и отсортированные списки `cities`, `categories`,
`event_types`, `languages`. Значения собираются из всех загруженных профилей;
это не динамический список только подходящих текущему запросу вариантов.

`GET /health` на текущем каталоге:

```json
{
  "status": "ok",
  "total_profiles": 66
}
```

Проверка готовности не обращается к OpenAI. Каталог читается при старте процесса;
невалидный CSV останавливает запуск, а не подменяется пустым списком.

API ожидает объяснения асинхронно в пределах общего бюджета запроса. После дедлайна
возвращаются подготовленные факты Python. Ограничения времени описаны в
[архитектуре](architecture.md#дедлайн), параметры — в [настройках](configuration.md).
