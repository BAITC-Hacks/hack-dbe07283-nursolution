# Каталог и редактор

## Два независимых источника

`CATALOG_BACKEND=csv` использует исходный файл из `data/`. Он читается один раз при
старте. `CATALOG_BACKEND=postgres` использует PostgreSQL; перед каждым подбором
читается свежий снимок профилей. Фильтры и ранжирование у режимов общие.

Переключение источника не является синхронизацией: изменения базы не переписывают
CSV, а изменения CSV не импортируются поверх уже созданной базы.

## PostgreSQL через Docker

В корневом `.env`:

```dotenv
CATALOG_BACKEND=postgres
DOCKER_DATABASE_URL=
POSTGRES_PASSWORD=nur_local_dev
POSTGRES_PORT=55432
ADMIN_TOKEN=вставьте_отдельный_случайный_ключ
```

Пароль выше предназначен для локальной разработки. Установите его до первой
инициализации тома. Смена `POSTGRES_PASSWORD` в `.env` не меняет пароль пользователя
в уже существующей базе; пароль существующей базы меняется средствами PostgreSQL.

Если `ADMIN_TOKEN` в вашем `.env` уже заполнен, сохраните его. Для новой копии
создайте ключ: `python -c "import secrets; print(secrets.token_urlsafe(32))"`.
Вставьте результат в `ADMIN_TOKEN`. Общего ключа по умолчанию в репозитории нет,
в `.env.example` поле пустое. `OPENAI_API_KEY` и `MATCHER_USE_LLM` задаются независимо:
база работает и с OpenAI, и без него.

```bash
docker compose --profile postgres up -d --wait db
docker compose up --build -d --wait web
```

При пустом `DOCKER_DATABASE_URL` Compose подключает API к `db:5432` с паролем
из `POSTGRES_PASSWORD`. Хостовый `DATABASE_URL` не используется контейнером.
База доступна на хосте через `127.0.0.1:55432`.
Если порт занят, измените `POSTGRES_PORT`. API запускается после готовности базы;
в CSV-режиме сервис `db` не требуется.

## Python на хосте + база в Docker

Запустите только `db` предыдущей командой. В `.env` укажите URL с портом хоста:

```dotenv
CATALOG_BACKEND=postgres
DATABASE_URL=postgresql://nur:nur_local_dev@127.0.0.1:55432/nur
```

Затем запустите Uvicorn по README. Если пароль изменён, обновите его и в URL;
специальные символы в пароле URL должны быть закодированы. `DATABASE_URL` можно
сохранить в `.env` при одновременном запуске API в Docker: Compose использует
отдельный `DOCKER_DATABASE_URL` либо встроенный адрес `db:5432`.

При этих настройках `localhost:8000` и `localhost:8080` используют одну базу.
Правки из `/admin` любого сервера доступны новым запросам подбора обоих серверов.
Чтобы контейнер работал с внешней базой, укажите её URL в `DOCKER_DATABASE_URL`;
сервис `db` в таком случае не нужен.

## Первый запуск и хранение

При первом старте API создаёт таблицы `catalog_meta` и `contractors`, затем
в одной транзакции загружает CSV. Advisory lock исключает двойной импорт при
одновременном запуске нескольких workers. Версия схемы сейчас — `1`.

`contractors` хранит `id`, профиль в JSONB и числовую `revision`. Редактор валидирует
поля перед записью. Для текущего небольшого каталога фильтры выполняются Python
по полному снимку, а не SQL-запросом. При росте каталога потребуется пересмотреть
хранение, индексы и способ фильтрации.

Данные остаются в томе `postgres_data` после `docker compose down` и пересборки
приложения. `docker compose down -v` удаляет том с каталогом: эта команда не нужна
для обычного перезапуска. Автоматическое резервное копирование пока не настроено.

## Работа с редактором

1. Откройте `/admin` на том же адресе, что и приложение.
2. Введите `ADMIN_TOKEN` из серверного `.env`.
3. Выберите профиль или нажмите «Добавить профиль».
4. Заполните условия, описание и занятые даты; списки разделяются `|`.
5. Сохраните изменения. Новые запросы подбора сразу прочитают их из базы.

ID существующего профиля неизменяемый. Если другой редактор успел сохранить
профиль, устаревшая версия получает HTTP 409. Правки не перезаписываются молча:
перечитайте каталог и внесите изменения в актуальную версию.

Ключ хранится только в памяти страницы, не в localStorage и не в URL.
Редактор использует `Authorization: Bearer ...`. Пустой `ADMIN_TOKEN` выключает
его API; неверный ключ возвращает 401. В CSV-режиме разрешён только просмотр,
запись возвращает 409. Добавление и изменение доступны; удаления профилей нет.

Это редактор с общим ключом для локального проекта. Пользовательских аккаунтов,
ролей, аудита изменений и инфраструктуры публичного HTTPS-развёртывания пока нет.

## HTTP-контракт редактора

| Метод | Путь | Тело / ответ |
| --- | --- | --- |
| GET | `/admin/api/contractors` | `backend`, `editable`, `records`: список `{profile, revision}` |
| POST | `/admin/api/contractors` | Тело — профиль; HTTP 201 и `{profile, revision}` |
| PUT | `/admin/api/contractors/{id}` | Тело — `{profile, revision}`; HTTP 200 и новая версия |

Профиль использует поля CSV, но `categories`, `event_formats`, `languages`, `busy_dates`
передаются JSON-массивами, `price_from_kzt` — целым числом ≥ 0, `max_hours` —
положительным числом или `null`. Даты имеют формат `YYYY-MM-DD`. ID состоит из
латинских букв, цифр, `_`, `-`, максимум 80 символов. Неизвестные поля отклоняются.
